# 美术资源接入与替换流程

## 当前实现

- 默认资源在 `frontend/public/assets/`，由 `frontend/src/data/assets.ts` 统一映射。
- `placeholders/` 提供角色、立绘、技能、藏宝点、小怪、召唤物、状态的默认图。
- `buffs/icons/` 提供统一的灼烧、眩晕、沉默、禁走、结盟、同步、延迟伤害及属性变化图标。
- `characters/map_sprites/`、`characters/portraits/`、`monsters/`、`summons/`、`treasures/`、`skills/icons/` 已建立默认资源入口；`ui/`、`effects/` 留作后续扩展。
- 现有地形贴图保持在 `frontend/public/terrain/`，由 `frontend/src/data/terrain.ts` 映射。`assets/tiles/` 是后续替换入口。
- 基础占位音效在 `frontend/public/audio/`，对应 `soundRegistry.ts`；炸弹音效由 Web Audio 合成。

## 图片字段和回退

| 对象 | 当前字段 | 接入方式 |
| --- | --- | --- |
| 角色 / 小怪 / 召唤物 | `tokenImageUrl`、`portraitImageUrl` | 地图棋子、角色卡、属性面板、名单栏 |
| 技能 | `iconUrl` | 开局技能库、编辑器、技能卡、战斗技能栏 |
| 地块 | `tileImageUrl` | 自定义图片优先，默认地形图片作底图 |
| 状态 | `statusEffects[].type` | `statusVisual()` 映射图标和中文说明 |
| 结盟 | `alliances[]` | 显示后端返回的关系、伙伴名称；前端不计算联盟规则 |

文档中原先建议的 `mapSpriteUrl` / `portraitUrl` 对应现有的 `tokenImageUrl` / `portraitImageUrl`。沿用现有合同，避免字段重复。

图片统一通过 `GameImage` 加载：有效图片优先；空 URL、404、损坏图片回退到对应默认图；默认图也加载失败时显示名称首字。失败回退不会形成重复请求循环，URL 更新后可以加载新图。藏宝点采用默认宝箱；召唤物和小怪有独立图形和文字标记。

占位图使用项目内自制 SVG，`viewBox` 为 64×64，可清晰缩放。正式资源仍推荐使用第 11 阶段文档约定的 PNG 尺寸；这里不要求为了占位而增加位图资源。

## 替换步骤

1. 角色 / 小怪：在编辑器上传地图图或立绘，保存模板。每次上传生成独立的小写 UUID 文件名，避免同名图片覆盖和浏览器旧缓存。
2. 技能：在技能管理器更新 `iconUrl` 并保存。可引用默认静态资源、已有上传资源或内置图标接口。
3. 地形 / Buff / UI 默认资源：替换同路径文件，或更新 `assets.ts` / `terrain.ts` 映射；无需更改战斗规则。
4. 开发模式下，前端代码通过 Vite 更新；替换同路径静态文件后刷新页面。模板图片保存后重新进入相应页面 / 战斗页即可加载新 URL。
5. 新开局会携带当前模板资源；已在战斗中的召唤物优先使用实体自己的图片字段。
6. 更新 `art_credits.md`，记录来源和使用条件；检查编辑、开局、战斗三个位置和缺图回退。

现有用户上传文件保留原路径，不批量重命名。资源替换不改变伤害、行动点、回合、胜负或技能目标规则。

## 基础动画

- 后端提供炸弹 `BattlePlayback`；普通行动由 `basicPresentation.ts` 将已结算的事件和状态差异转换为基础播放时间线。
- 二者共用 `PlaybackQueue`；显示状态按时间点推进，最后提交完整后端结果。
- 移动保存起点 / 终点，用 CSS 平滑移动；普通攻击前冲，伤害后播放受伤，再播放死亡；反击排在首次命中之后。
- 治疗显示绿色数值；状态添加有图标和反馈；挖宝根据返回日志和状态显示成功 / 失败；召唤物出现有淡入。
- 飘字独立于 Pixi 特效层，随地图视角定位；特效围绕目标缩放，避免围绕画布原点偏移。
- 播放期间锁定行动，支持 Esc 跳过和后台自动结束；减少动态效果模式直接显示最终状态。

这里是第 11 阶段的基础反馈。各技能独立的动作设计、复杂事件的精细时间线和最终 UI 设计属于第 12 阶段。
